# Claude Code VS Code extension: support for continuing a session on web / mobile (state as of September 2026)

Research date: 2026-09-19. Docs fetched live from code.claude.com (current as of latest changelog entry 2.1.277); GitHub data via the GitHub REST API and CHANGELOG.md on main. Items are labelled OFFICIAL DOC, CHANGELOG, GITHUB ISSUE, or INFERENCE.

## 1. Does the VS Code extension support Remote Control (slash command, UI, setting)? Are its slash commands the same as the CLI?

### Takeaway
Yes. The extension has supported Remote Control since 2.1.79 (March 2026). Type `/remote-control` or `/rc` in the prompt box. The current docs also describe a footer indicator and an "Enable Remote Control for all sessions" toggle (auto-connect) in the extension's command menu. The extension exposes only a subset of the CLI's commands, and `/remote-control` is in that subset.

### Cited Findings

Once the session connects, click the indicator to go directly to the session, or find it in the session list at claude.ai/code. Claude Code also posts the session URL in the conversation. ## 2. Web/cloud handoff from the extension; session history UI linking to web sessions

### Takeaway
There is no documented way in the extension to push the current local conversation to Claude Code on the web (a cloud session). The extension can only pull web sessions down: Session history has a Web tab that downloads a cloud session and continues it locally (one-way, no sync back). To move a local session to the cloud, the documented routes are the Desktop app's "Continue in > Claude Code on the Web" or starting a new cloud task from the CLI with `--cloud`. Otherwise use Remote Control, which keeps the session running on your machine.

### Cited Findings
- OFFICIAL DOC, VS Code "Resume cloud sessions from Claude.ai": "If you run cloud sessions, you can resume them directly in VS Code. This requires signing in with **Claude.ai Subscription**, not Anthropic Console." Steps: Session history button, then the **Web** tab (Local and Web), then click a session "to download it and continue the conversation locally." Note: "Only cloud sessions started with a GitHub repository appear in the Web tab. Resuming loads the conversation history locally; changes are not synced back to claude.ai." — [VS Code docs](https://code.claude.com/docs/en/vs-code)
- OFFICIAL DOC, session history: "Click the **Session history** button at the top of the Claude Code panel to access your conversation history. You can search by keyword or browse by time." — [VS Code docs](https://code.claude.com/docs/en/vs-code)
- OFFICIAL DOC: on a third-party provider (Bedrock, Vertex, Foundry) the extension "doesn't offer features that require a claude.ai account, such as usage tracking, voice dictation, and the Web tab for cloud sessions". — [VS Code docs](https://code.claude.com/docs/en/vs-code)
- CHANGELOG, history of the Web tab: 2.1.33 "VSCode: Added support for remote sessions, allowing OAuth users to browse and resume sessions from claude.ai"; 2.1.63 "Fixed remote sessions not appearing in conversation history"; 2.1.70 teleport marker fix; 2.1.261 teleport-related fixes for Web-tab sessions. — [CHANGELOG.md](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)
- OFFICIAL DOC, the CLI handoff is one-way: "From the CLI, session handoff is one-way: you can pull cloud sessions into your terminal with `--teleport`, but you can't push an existing terminal session to the cloud. The `--cloud` flag with a task description creates a new cloud session for your current repository... The Desktop app provides a **Continue in** menu that can send a local session to the cloud." — [Claude Code on the web docs](https://code.claude.com/docs/en/claude-code-on-the-web)
- OFFICIAL DOC: `claude --cloud "<task>"` creates a new cloud session. The VM clones your GitHub remote at your current branch (not your local checkout), so push first. The older `--remote` spelling is a "deprecated alias for `--cloud`". `--cloud` and `--remote-control` are unrelated: "`--remote-control` ... lets you monitor and steer a local CLI session from claude.ai or the Claude app." — [Claude Code on the web docs](https://code.claude.com/docs/en/claude-code-on-the-web); [CLI reference](https://code.claude.com/docs/en/cli-reference)
- OFFICIAL DOC, Desktop "Continue in" menu: "Claude Code on the Web: sends your local session to continue running in the cloud. Desktop pushes your branch, generates a summary of the conversation, and creates a new cloud session with the full context... requires a clean working tree, and is not available for SSH sessions." The other option is "Your IDE". — [Desktop docs](https://code.claude.com/docs/en/desktop)
- OFFICIAL DOC: the CLI has `/teleport` (alias `/tp`) and `claude --teleport` to pull cloud sessions to the terminal. `--teleport` is distinct from `--resume`: "`--resume` reopens a conversation from this machine's local history and doesn't list cloud sessions". The terminal copy is separate: "new work there stays local and doesn't appear in the cloud session... To keep steering from your phone after teleporting, start `/remote-control` in the local session." — [Claude Code on the web docs](https://code.claude.com/docs/en/claude-code-on-the-web); [Commands reference](https://code.claude.com/docs/en/commands)
- OFFICIAL DOC: cloud sessions need GitHub, and cloud features are unavailable with Zero Data Retention. Cloud sessions are "in research preview for Pro, Max, and Team users, and for Enterprise users with premium seats or Chat + Claude Code seats." — [Claude Code on the web docs](https://code.claude.com/docs/en/claude-code-on-the-web)
- The extension docs list no `--cloud`, `&` prefix, `/web` or "send to cloud" control. I searched the VS Code page, the commands page, the CLI reference and the changelog. The `&` prefix appears in none of the current docs I fetched.

### Inferences
- INFERENCE: A local extension conversation cannot be handed to a cloud session with its history from inside the extension. Continuing "the same session" from claude.ai/code or the phone means Remote Control (the local process keeps running, transcript synced). The alternative is a new cloud task, which does not carry the conversation (Desktop's Continue in sends a summary and a pushed branch).
- INFERENCE: A Remote Control session shows up in the claude.ai/code session list and the mobile Code tab, but it is not a cloud session. Execution stays on your machine.

### Gaps
- I could not confirm whether an `&` prefix or `/web` command ever worked in the extension, or whether it was removed. Nothing in the current docs mentions it.
- I did not verify whether the extension surfaces a "Continue in Desktop" or similar control. The docs mention only `/desktop` for the CLI.

## 3. Where sessions are stored; extension to terminal resume; Remote Control from there; do they see the same conversation?

### Takeaway
Yes. The official VS Code docs state the extension and the CLI share conversation history and tell you to run `claude --resume` in the terminal to continue an extension conversation. Transcripts are JSONL files under `~/.claude/projects/<project>/<session-id>.jsonl`. After resuming in the terminal, `/remote-control` (or `claude --remote-control`) enables Remote Control there.

### Cited Findings
- OFFICIAL DOC: "The extension and CLI share the same conversation history. To continue an extension conversation in the CLI, run `claude --resume` in the terminal. This opens an interactive picker where you can search for and select your conversation." — [VS Code docs](https://code.claude.com/docs/en/vs-code) ("Switch between extension and CLI")
- OFFICIAL DOC: the extension does not put `claude` on your PATH. "The extension bundles a private copy of the CLI for its chat panel, but typing `claude` in a terminal requires the standalone CLI install." Once installed, "`claude --resume` ... work in any terminal." — [VS Code docs](https://code.claude.com/docs/en/vs-code)
- OFFICIAL DOC, storage: "By default, Claude Code stores transcripts as JSONL at `~/.claude/projects/<project>/<session-id>.jsonl`, where `<project>` is your working directory path with non-alphanumeric characters replaced by `-`." Retention is 30 days by default (`cleanupPeriodDays`). `CLAUDE_CONFIG_DIR` relocates storage. — [Sessions docs](https://code.claude.com/docs/en/sessions)
- OFFICIAL DOC, session-scoping: "A session is a saved conversation tied to a project directory." The `claude --resume` picker shows sessions from the current worktree by default. `Ctrl+W` widens to all worktrees and `Ctrl+A` to every project on the machine. The sessions page also says the desktop app, claude.ai/code and the VS Code extension "each maintain their own session history. This page covers the CLI." — [Sessions docs](https://code.claude.com/docs/en/sessions)
- OFFICIAL DOC: resume entry points are `claude --continue` (most recent conversation in the current directory), `claude --resume` (picker), `claude --resume <name>`, and `claude --resume <transcript-path>`. `claude --resume <session-id>` "from any directory" searches the current project and worktrees, then every other project on the machine (v2.1.223+). — [Sessions docs](https://code.claude.com/docs/en/sessions); [CLI reference](https://code.claude.com/docs/en/cli-reference)
- OFFICIAL DOC: the extension's `session` URI parameter takes a session ID; "The session must belong to the workspace currently open in VS Code." — [VS Code docs](https://code.claude.com/docs/en/vs-code)
- OFFICIAL DOC, Remote Control after resuming in the terminal: CLI "From an existing session" tab: `/remote-control` (or `/rc`) "starts a Remote Control session that carries over your current conversation history." `claude --remote-control` starts an interactive session with Remote Control on. — [Remote Control docs](https://code.claude.com/docs/en/remote-control); [CLI reference](https://code.claude.com/docs/en/cli-reference)
- OFFICIAL DOC, resuming a Remote Control session in another process: "If you resume the conversation in a second terminal while the first one still has Remote Control on, Claude Code prints a notice in the second terminal and leaves Remote Control off there instead of taking the session away from the first... Run `/remote-control` in the second terminal to move Remote Control to it." — [Remote Control docs](https://code.claude.com/docs/en/remote-control)
- OFFICIAL DOC: "When you resume a conversation in Claude Desktop or an IDE extension that had Remote Control on, Claude Code reattaches it to the existing claude.ai session instead of adding a new one to the session list." — [Remote Control docs](https://code.claude.com/docs/en/remote-control)
- OFFICIAL DOC, two live processes on one session: "If you resume the same session in two terminals without forking, messages from both interleave into one transcript." To avoid this, use `claude --continue --fork-session` or `/branch` (a branch gets its own session ID). — [Sessions docs](https://code.claude.com/docs/en/sessions)
- OFFICIAL DOC: for a resumed session, "Conversation history: the full history, including tool calls and results", plus model, agent and permission mode. Flags such as `--mcp-config` and `--settings` are not restored. — [Sessions docs](https://code.claude.com/docs/en/sessions)
- OFFICIAL DOC: "Local process must keep running: Remote Control runs as a local process. If you close the terminal, quit VS Code, or otherwise stop the `claude` process, the session goes offline until you bring it back." — [Remote Control docs](https://code.claude.com/docs/en/remote-control)
- OFFICIAL DOC: turning Remote Control off from the extension removes the reconnection record, so a later resume does not reconnect. When an owning app turned it off, Claude Code keeps the record and reconnects. — [Remote Control docs](https://code.claude.com/docs/en/remote-control) ("Resume outcomes" section)
- GITHUB ISSUE #94546 (open, updated 2026-09-15): "Remote Control (--spawn=same-dir) sessions never appear in the --resume picker" (a server-mode issue, not the extension). — [Issue #94546](https://github.com/anthropics/claude-code/issues/94546); listed via GitHub search API. Details not read.

### Inferences
- INFERENCE (from the documented facts): the documented path is (a) install the standalone CLI, (b) in the same project folder run `claude --resume` (or `--continue`) and pick the extension conversation, (c) run `/remote-control` (or launch with `claude --resume` and then `/rc`). Watch the case where the extension tab still has the session open: two processes writing one transcript interleave, and Remote Control may stay off in the second one.
- INFERENCE: this route is usually unnecessary now that the extension supports `/remote-control` directly. It is a fallback for features the extension lacks (QR code, name argument, CLI-only slash commands).
- INFERENCE: the terminal sees the same conversation because both read the same `~/.claude/projects/...` transcript store on the same machine. This does not hold across machines, on VS Code Remote-SSH/WSL/container hosts unless CLI and extension share the same `~/.claude` (untested), or when `CLAUDE_CONFIG_DIR` differs.

### Gaps
- I did not test the extension-to-CLI resume on a live install. The claim rests on the official docs.
- Whether extension-started sessions appear in `claude --resume` on very old versions is not documented.
- No source found about VS Code Remote-SSH / Dev Containers / WSL specifics for shared session storage.

## 4. Differences: extension vs terminal CLI vs Desktop; minimum versions; known issues / open GitHub issues

### Takeaway
The extension supports `/remote-control`, the auto-connect toggle, resuming Web sessions, and the CLI-shared history, but its slash commands are a subset and it lacks QR code / naming for `/remote-control`. CLI-only: `claude remote-control` server mode, `--remote-control`, `--cloud`, `--teleport` and `/teleport`. Desktop is the only surface with a "Continue in > Claude Code on the Web" push of a local session. Minimum VS Code version is documented as 1.94.0, but the Marketplace lists 1.98.0. Several Remote Control status bugs in the extension have been fixed through 2.1.275, and at least one HTTP 403 bug is open.

### Cited Findings
- OFFICIAL DOC, prerequisites: "VS Code 1.94.0 or higher" and "An Anthropic account: any paid Claude subscription (Pro, Max, Team, or Enterprise) or a Claude Console account works, and no API key is required." — [VS Code docs](https://code.claude.com/docs/en/vs-code)

Treat 1.98.0 as the likelier install-time gate. — [Marketplace listing](https://marketplace.visualstudio.com/items?itemName=anthropic.claude-code) (fetched via summary tool; the "Last updated" date it printed, "September 7, 2026", is unverified) vs [VS Code docs](https://code.claude.com/docs/en/vs-code)

The CLI has `claude remote-control` server mode (multiple concurrent sessions, QR code, `--name`, `--spawn`, `--capacity`), and `claude --remote-control` / `--rc`. — [VS Code docs](https://code.claude.com/docs/en/vs-code); [Remote Control docs](https://code.claude.com/docs/en/remote-control); [CLI reference](https://code.claude.com/docs/en/cli-reference)

## 5. Requirements: account/auth type and plan tiers

### Takeaway
Remote Control needs a claude.ai subscription login (Pro, Max, Team or Enterprise); API keys, Console-only auth, `setup-token`/`CLAUDE_CODE_OAUTH_TOKEN` tokens, and Bedrock/Vertex/Foundry are unsupported. On Team and Enterprise an admin (Owner) must first turn on the Remote Control toggle. The extension itself works with Console accounts too, but Remote Control and the Web tab need claude.ai sign-in.

### Cited Findings
- OFFICIAL DOC: "Remote Control is available on all plans. On Team and Enterprise, it is off by default until an Owner enables the Remote Control toggle in Claude Code admin settings." Requirements: "available on Pro, Max, Team, and Enterprise plans. API keys are not supported." — [Remote Control docs](https://code.claude.com/docs/en/remote-control)
- OFFICIAL DOC, further requirements:
  - Sign in through claude.ai with `/login`.
  - Not available on Bedrock, Google Cloud Agent Platform/Vertex, Foundry, a custom `ANTHROPIC_BASE_URL` (since v2.1.196), or an enterprise Claude apps gateway.
  - `DISABLE_TELEMETRY`, `DO_NOT_TRACK`, `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC` and `DISABLE_GROWTHBOOK` each disable the feature-flag evaluation Remote Control needs.
  - Accept the workspace trust dialog in the project directory at least once.
  — [Remote Control docs](https://code.claude.com/docs/en/remote-control)
- OFFICIAL DOC: long-lived tokens (`claude setup-token`, `CLAUDE_CODE_OAUTH_TOKEN`) "can only make model requests, so they can't establish Remote Control sessions. Run `claude auth login`." Setting `ANTHROPIC_API_KEY`, an `apiKeyHelper` or `ANTHROPIC_AUTH_TOKEN` gives "Remote Control requires claude.ai subscription auth." — [Remote Control docs](https://code.claude.com/docs/en/remote-control)

Admin can turn it off with the `disableRemoteControl` setting. — [Remote Control docs](https://code.claude.com/docs/en/remote-control)
- OFFICIAL DOC: Trusted Devices (Team/Enterprise, off by default) requires device enrollment before viewing/steering Remote Control sessions from claude.ai, the mobile apps or Desktop. ### Inferences
- INFERENCE: the most common reasons `/remote-control` fails in the extension are (1) signed in with API key/Console, (2) Team/Enterprise admin has not enabled it, (3) a proxy/gateway `ANTHROPIC_BASE_URL` or telemetry-disable env var, (4) an outdated extension.

## Practical recipe for a user currently in an extension session (synthesised from the above; INFERENCE where not directly cited)

1. Update the extension (current is 2.1.277). Sign in with a claude.ai Pro/Max/Team/Enterprise account, not an API key. (Team/Enterprise: an Owner must enable the Remote Control toggle.)
2. In the extension prompt box, type `/remote-control` (or `/rc`), accept the one-time confirmation, and click the Remote Control footer indicator or open claude.ai/code / the Claude mobile app Code tab. The conversation history carries over. VS Code must stay open and the machine awake. Optional: turn on "Enable Remote Control for all sessions" (command menu, Settings) to auto-connect.
3. If it fails or you want CLI-only options (QR code, custom name, multiple sessions): install the standalone CLI, `cd` to the same project, run `claude --resume` (pick the extension conversation) then `/remote-control`. Close the extension tab first to avoid two processes on one transcript, or use `--fork-session`.
4. If you want the work to continue after your laptop is off: the extension cannot push a session to the cloud. Use the Desktop app's Continue in > Claude Code on the Web, or start a fresh `claude --cloud "<task>"` (needs a GitHub remote, pushed branch). Neither carries the extension conversation as-is.
