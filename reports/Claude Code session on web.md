# Remote Control Mirrors Your VS Code Session Anywhere

A Claude Code session running in the VS Code extension can be made available on claude.ai/code and the Claude mobile app by typing **`/remote-control` (alias `/rc`)** in the prompt box. This is Remote Control, and it carries over the current conversation history ([Remote Control docs](https://code.claude.com/docs/en/remote-control)). The web and phone become windows into the session that is still running on your computer. Code execution, the filesystem, MCP servers and project config stay local, and only the transcript syncs through Anthropic's servers. The extension has supported the command since **v2.1.79 (March 2026)** ([CHANGELOG](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)). It needs a claude.ai subscription login (Pro, Max, Team or Enterprise) rather than an API key. On Team and Enterprise, an Owner must first switch on a toggle. VS Code has to stay open and the machine reachable, because the local process is the session. Nothing in the extension or CLI can push an existing local conversation into a cloud session. The CLI's handoff is one-way (cloud to terminal, via teleport), and `claude --cloud "<task>"` only creates a fresh session from a task description ([Cloud docs](https://code.claude.com/docs/en/claude-code-on-the-web)). Remote Control is no longer labelled a research preview in the current docs, but cloud sessions still are. Status here is as of 19 September 2026, against Claude Code v2.1.277.

## One command in the prompt box hands the running session to your phone

For a session already open in the extension, the whole procedure is short. Type `/remote-control` (or `/rc`) in the prompt box and accept the one-time "Enable Remote Control" dialog. Choosing "Never mind" or pressing Esc leaves it disconnected and asks again next time ([Remote Control docs](https://code.claude.com/docs/en/remote-control)). While connected, the extension shows a **Remote Control indicator in the prompt-box footer**. Clicking it opens the session on claude.ai, and Claude Code also posts the session URL in the conversation. To disconnect, run `/remote-control` again. The session keeps running locally after a disconnect ([Remote Control docs](https://code.claude.com/docs/en/remote-control)). To find it from another device, open claude.ai/code or the Claude iOS/Android app and tap the **Code** tab. Online Remote Control sessions show a computer icon with a green status dot ([Remote Control docs](https://code.claude.com/docs/en/remote-control)).

The VS Code version of the command is slimmer than the CLI's. It accepts no name argument and shows no QR code, and the title is derived from your conversation history or first prompt ([Remote Control docs](https://code.claude.com/docs/en/remote-control)). The docs give the title precedence as an explicit name first, then `/rename`, then the last meaningful message in history, then an auto-generated name such as `myhost-graceful-unicorn`. The extension can also connect every new session automatically. Its Settings section has an **Enable Remote Control for all sessions** toggle, which writes `remoteControlAtStartup` and needs v2.1.203 or later. From v2.1.261 it also reaches sessions in other VS Code windows ([VS Code docs](https://code.claude.com/docs/en/vs-code)). The same setting can be placed in `~/.claude/settings.json` or managed settings. A project-level `true` is deliberately ignored, so a checked-in file cannot enable it for a whole team ([Remote Control docs](https://code.claude.com/docs/en/remote-control)). A Slash commands dialog in the Customize section lists `/remote-control` and needs v2.1.257 or later ([VS Code docs](https://code.claude.com/docs/en/vs-code)).

Anyone who wants the CLI-only extras has three other entry points, and the docs distinguish them clearly. `claude --remote-control` (or `--rc`, optionally with a name such as `claude --remote-control "My Project"`) starts a fresh interactive terminal session that is also remotely controllable. `claude remote-control` runs "server mode", with no local interactive session. It shows a URL, toggles a QR code with the spacebar, and accepts `--name`, `--spawn same-dir|worktree|session`, `--capacity <N>` (default 32), `--permission-mode`, `--sandbox` and, from v2.1.200, `-c/--continue` and `--session-id` ([Remote Control docs](https://code.claude.com/docs/en/remote-control)). The third route is a fallback for a conversation that began in the extension. Install the standalone CLI, since the extension bundles a private copy that does not put `claude` on your PATH, then run `claude --resume` in the same project and pick the conversation. Then run `/remote-control` there ([VS Code docs](https://code.claude.com/docs/en/vs-code)). The extension and CLI share one conversation history, stored as JSONL under `~/.claude/projects/<project>/<session-id>.jsonl` ([Sessions docs](https://code.claude.com/docs/en/sessions)). Close the extension tab first, or use `--fork-session`. Two live processes on one session interleave their messages into one transcript, and a second process leaves Remote Control off until you run `/remote-control` there ([Sessions docs](https://code.claude.com/docs/en/sessions); [Remote Control docs](https://code.claude.com/docs/en/remote-control)). Do not confuse `--remote-control` with `--remote`. The latter is a deprecated alias for `--cloud` and concerns cloud sessions ([CLI reference](https://code.claude.com/docs/en/cli-reference)).

Once connected, the phone or browser is more than a viewer. The docs list `/compact`, `/clear`, `/context`, `/usage`, `/model`, `/effort`, `/rename` and `/mcp` as usable remotely, while terminal-UI commands such as `/plugin` and `/resume` work only locally ([Remote Control docs](https://code.claude.com/docs/en/remote-control)). Compaction and `/clear` propagate to connected devices. Prompts sent from the phone mid-turn are queued. Permission prompts stay open until answered, and other forwarded dialogs expire after 5 minutes by default (`dialogExpiry`). To get phone push notifications, install the app, sign in with the same account, and enable "Push when Claude decides" or "Push when actions required" under `/config`. Pushes are skipped while you are focused on the terminal ([Remote Control docs](https://code.claude.com/docs/en/remote-control)).

## A full claude.ai login, an Owner toggle and open outbound HTTPS are the price of entry

Remote Control requires **claude.ai subscription auth**. The docs say it is "available on all plans" and list Pro, Max, Team and Enterprise, adding "API keys are not supported" ([Remote Control docs](https://code.claude.com/docs/en/remote-control)). That makes a Console-only sign-in insufficient. The extension itself works with Console accounts, but Remote Control and the extension's Web tab do not ([VS Code docs](https://code.claude.com/docs/en/vs-code)). On Team and Enterprise the feature is **off by default until an Owner enables the Remote Control toggle** at claude.ai/admin-settings/claude-code ([Remote Control docs](https://code.claude.com/docs/en/remote-control)). The docs give no single minimum Claude Code version, only per-feature gates (v2.1.200 for `--continue`, v2.1.203 for the VS Code toggle, v2.1.224 for cross-session messaging). The practical check is to update the extension and try `/remote-control`. The VS Code docs state a minimum of VS Code 1.94.0, while the Marketplace listing shows 1.98.0, so the higher number is the safer gate ([Marketplace](https://marketplace.visualstudio.com/items?itemName=anthropic.claude-code); [VS Code docs](https://code.claude.com/docs/en/vs-code)).

A long list of environment conditions silently defeats it. Bedrock, Vertex (Google Cloud Agent Platform), Foundry, enterprise gateway sign-in and any `ANTHROPIC_BASE_URL` other than api.anthropic.com are unsupported. The last became a block in v2.1.196. Setting `ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN` or an `apiKeyHelper` produces "Remote Control requires claude.ai subscription auth". Tokens from `claude setup-token` or `CLAUDE_CODE_OAUTH_TOKEN` can only make model requests, and the fix is `claude auth login`. `DISABLE_TELEMETRY`, `DO_NOT_TRACK`, `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC` and `DISABLE_GROWTHBOOK` each disable the feature-flag evaluation it depends on ([Remote Control docs](https://code.claude.com/docs/en/remote-control)). Organisations with Zero Data Retention or HIPAA configurations cannot enable it. The `disableRemoteControl` managed setting turns it off everywhere. A stale Team or Enterprise login on a personal Pro or Max plan applies the org's policy, and `claude auth logout` followed by `claude auth login` clears that. Run `claude doctor` to see which eligibility check failed. The workspace-trust dialog must have been accepted once in the project directory, and it is never saved for the home directory ([Remote Control docs](https://code.claude.com/docs/en/remote-control)).

Network needs are modest. Outbound HTTPS to the Anthropic API on port 443 is required and no inbound ports are opened. A blocking proxy shows up as "Remote credentials fetch failed" ([Remote Control docs](https://code.claude.com/docs/en/remote-control)). Team and Enterprise orgs may also enable Trusted Devices (beta). It requires an enrolled device and a sign-in no older than 18 hours to view or steer sessions from claude.ai, mobile or Desktop ([Remote Control docs](https://code.claude.com/docs/en/remote-control)). The docs cite no separate Remote Control quota. The usage-limit statements found concern cloud sessions, which share limits with all other Claude usage ([Cloud docs](https://code.claude.com/docs/en/claude-code-on-the-web)).

## Everything still runs on your machine, and only the transcript travels through Anthropic

The architecture is a relay, not a migration. "Claude keeps running locally the entire time, so your code execution and filesystem access stay on your machine," and "the web and mobile interfaces are a window into that local session" ([Remote Control docs](https://code.claude.com/docs/en/remote-control)). The local process registers with the Anthropic API, polls for work, and streams over outbound TLS. The server routes messages between the client and the local session ([Remote Control docs](https://code.claude.com/docs/en/remote-control)). It uses "multiple short-lived credentials, each scoped to a single purpose", which limits the blast radius of any single compromised one ([Security](https://code.claude.com/docs/en/security)). Git diffs are computed on your machine on request. Images from the phone go straight to Claude, and other uploaded files are downloaded to your machine and passed as `@` references ([Remote Control docs](https://code.claude.com/docs/en/remote-control)).

The data-handling caveat matters more than launch-week coverage implied. While connected, "the session transcript, including your messages, Claude's responses, and tool activity, is stored on Anthropic servers" and retained under the data usage policy. Consumer plans keep it 5 years if training is permitted and 30 days if not, and commercial plans keep it 30 days ([Data usage](https://code.claude.com/docs/en/data-usage)). Early summaries said only chat messages travel and that nothing is stored ([VentureBeat](https://venturebeat.com/orchestration/anthropic-just-released-a-mobile-version-of-claude-code-called-remote)). The current official text is more specific, so treat it as authoritative. The docs do not say whether full tool-result bodies are stored. Anything sensitive that Claude reads in a connected session may therefore land in the stored transcript, which is a reasonable inference from "tool activity". Security is otherwise unchanged. The normal permission system applies, and "no cloud VMs or sandboxing are involved" unless you pass `--sandbox` in server mode ([Security](https://code.claude.com/docs/en/security)). A phone approval has the same power as one at the keyboard, and the real boundary is your claude.ai account (plus Trusted Devices where an org enables it).

Availability follows the local process. If you close the terminal or quit VS Code, the session goes offline within seconds. If the laptop sleeps or the network drops, the process reconnects automatically and queues messages meanwhile. An interactive session retries indefinitely but drops after about 30 minutes of failed heartbeats, after which `/remote-control` reconnects it. Server mode exits after roughly 10 minutes without a network. HTTP 403 refusals are retried for up to three minutes ([Remote Control docs](https://code.claude.com/docs/en/remote-control)). For unattended hosts, the docs recommend `tmux` or `screen`. Resuming later works through `claude --continue` or `--resume`, subject to a stored "reconnection record". Turning Remote Control off from the extension removes that record, so a later resume will not reconnect on its own ([Remote Control docs](https://code.claude.com/docs/en/remote-control)). Ending it is a matter of `/remote-control` again, killing the process, archiving from claude.ai or the app, or the `remoteControlAtStartup: false` and `disableRemoteControl` settings.

## Cloud sessions and teleport move different things in different directions

The three mechanisms are easy to conflate and only one of them keeps your session alive. A **cloud session** runs on an Anthropic-managed VM, or on an org's self-hosted environment, from a fresh clone of your repository. It starts from a task you describe, not from your local conversation ([Cloud docs](https://code.claude.com/docs/en/claude-code-on-the-web)). **Teleport** goes the other way. `claude --teleport [id]` (or `/teleport`, alias `/tp`, or `/tasks` then `t`) pulls a cloud session into the terminal, checks out its branch, and loads its full history ([Cloud docs](https://code.claude.com/docs/en/claude-code-on-the-web)). That copy is separate, since "new work there stays local and doesn't appear in the cloud session", and the docs advise starting `/remote-control` afterwards to steer it from a phone. Teleport also needs a clean git state (it offers to stash), the same repository rather than a fork, a pushed branch, and the same claude.ai account. The extension's Web tab, reached through Session history, does the same thing for cloud sessions started with a GitHub repository, with no sync back ([VS Code docs](https://code.claude.com/docs/en/vs-code)).

| | Remote Control | Cloud session (`claude --cloud "<task>"`) | Teleport | Desktop "Continue in > Claude Code on the Web" |
|---|---|---|---|---|
| Direction | Local session mirrored to web/mobile | Local to a new web session | Web to terminal | Local to a new web session |
| Runs on | Your machine | Anthropic VM | Your machine | Anthropic VM |
| Carries current conversation | Yes | No, task text only | Yes (cloud history pulled in) | A generated summary, described as "full context" |
| Uncommitted changes | Stay in the same checkout | Clone excludes them; local-bundle path includes tracked files | Needs a clean tree | Needs a clean tree |
| GitHub needed | No | Yes, or a local bundle (under 100 MB) | Yes, pushed branch | Yes, pushes the branch |
| Survives laptop off | No (machine must stay on) | Yes | No | Yes |
| Local MCP, `.env`, user config | Available | Not available (repo only) | Available | Not available |

Sources for the table: [Remote Control docs](https://code.claude.com/docs/en/remote-control), [Cloud docs](https://code.claude.com/docs/en/claude-code-on-the-web), [Cloud environments](https://code.claude.com/docs/en/cloud-environments), [Desktop docs](https://code.claude.com/docs/en/desktop).

The docs draw the line explicitly. Use Remote Control "when you're in the middle of local work and want to keep going from another device", and use a cloud session to start without local setup, work on an uncloned repo, or run tasks in parallel ([Remote Control docs](https://code.claude.com/docs/en/remote-control)). The push direction is the sticking point. The docs say it plainly: "From the CLI, session handoff is one-way: you can pull cloud sessions into your terminal with `--teleport`, but you can't push an existing terminal session to the cloud." Only Desktop's Continue in menu can send a local session to the cloud ([Cloud docs](https://code.claude.com/docs/en/claude-code-on-the-web)). It pushes your branch and generates a summary, and it is unavailable over SSH ([Desktop docs](https://code.claude.com/docs/en/desktop)). A GitHub feature request for universal local-to-remote teleporting was closed as a duplicate without an Anthropic comment visible ([Issue #14666](https://github.com/anthropics/claude-code/issues/14666)).

The cloud path has its own conditions. The VM clones your GitHub remote at your current branch, "not your local checkout", so push first. With no git remote, or with the Claude GitHub App not installed, `claude --cloud` instead bundles the local repo. The bundle includes all branches plus uncommitted changes to tracked files, but leaves out untracked files and credential-like files (`.env`, `*.tfvars`, `id_rsa`, `*.pem`), and it must stay under 100 MB ([Cloud docs](https://code.claude.com/docs/en/claude-code-on-the-web)). GitHub is required to open PRs, and GitLab or Bitbucket code can only be sent as a bundle that cannot push back. Cloud sessions load only the repo's `CLAUDE.md`, `.claude/settings.json` and `.mcp.json`. User-level config and MCP servers added with `claude mcp add` do not carry over ([Cloud environments](https://code.claude.com/docs/en/cloud-environments)). They offer Auto, Accept edits and Plan modes only, need claude.ai auth and the `allow_remote_sessions` org policy, and are unavailable under ZDR. Their status is unchanged: the docs still say "research preview for Pro, Max, and Team users, and for Enterprise users with premium seats or Chat + Claude Code seats" ([Cloud docs](https://code.claude.com/docs/en/claude-code-on-the-web)). Usage draws on normal plan limits with no separate VM charge. The older `&` message prefix ("send background tasks to Claude Code on the web," v2.0.45) appears in no current doc, and its status is unconfirmed ([CHANGELOG](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)). For this project, that means cloud sessions can handle Node tooling, but not iOS simulator work or uncommitted secrets (an inference, not a documented statement).

## Known issues: churn in the extension, a one-process-per-session rule and a stale-docs trap

Remote Control launched on **24 February 2026 as a research preview**, first for Max users ([VentureBeat](https://venturebeat.com/orchestration/anthropic-just-released-a-mobile-version-of-claude-code-called-remote)). Simon Willison called it "a little bit janky" at the time ([Simon Willison](https://simonwillison.net/2026/Feb/25/claude-code-remote-control/)). The current docs mark only Trusted Devices as beta, so the core feature is no longer labelled a preview. No official GA announcement or date was found, so the transition date is unconfirmed. Anyone reading older material should discount it. Issue #28951, "Remote control (/rc) not supported in VS Code extension", was opened on 2026-02-26 and closed as completed on 2026-03-20 after v2.1.79 shipped, and its thread still holds "not supported" reports that are now stale ([Issue #28951](https://github.com/anthropics/claude-code/issues/28951)). One duplicate request, #30905, was closed as "not_planned" only because it duplicated #28951, so it is not a rejection ([Issue #30905](https://github.com/anthropics/claude-code/issues/30905)).

Extension behaviour is still being stabilised. The changelog records repeated fixes to the connected or failed status display (v2.1.224, v2.1.265, v2.1.275), a footer pill replacing the banner in v2.1.251, and a fix so that running `/remote-control` while it is still connecting turns it off immediately ([CHANGELOG](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)). The notes disagree on exactly which version carried the last fix, with 2.1.269, 2.1.271 and 2.1.275 all cited across sources. Open issues include **#95413**, a Windows 11 report on extension v2.1.272 in which `/remote-control`, `--remote-control` and `remoteControlAtStartup` all fail with HTTP 403 while `claude remote-control --name` still works. The reporter dates the regression to 2.1.266 through 2.1.269 ([Issue #95413](https://github.com/anthropics/claude-code/issues/95413)). This is one unconfirmed report, but its implied workaround is server mode from the CLI. Others cover mobile prompts stuck after being answered (#95343) and a "GitHub repository access check failed" on mobile (#44805). A further issue, #94546, notes that server-mode `--spawn=same-dir` sessions never appear in the `--resume` picker ([GitHub issues search](https://github.com/anthropics/claude-code/issues?q=is%3Aissue+remote+control)).

Structural limits remain as well. There is one remote session per interactive process. Some terminal-only commands are unavailable remotely. The Fable usage-credits consent prompt is not forwarded to the remote device, so an unanswered prompt ends the turn without sending the request. `/resume` or `/teleport` in the terminal changes which conversation the device sees without replaying earlier history. After compaction or a resume, Claude Code archives the old server session on reconnect, and replacement sessions can omit earlier messages ([Remote Control docs](https://code.claude.com/docs/en/remote-control)). Keeping the same VS Code process running is the reliable path.

## Conclusion

The question has a narrower answer than the vocabulary around it suggests. Only one documented mechanism makes the same live conversation, with its history and uncommitted working tree, reachable from claude.ai/code and the mobile app: Remote Control from the extension's own prompt box. Every option that puts the work on Anthropic's infrastructure either starts a new session or sends a summary, needs a pushed GitHub branch, and loses local config and secrets. The trade is between sessions that stay yours and require your machine, and sessions that outlive your laptop and forget your conversation.

Two points shift the picture from earlier commentary. The stored transcript on Anthropic servers, including tool activity, is a real data-handling fact that the "encrypted, nothing stored" launch coverage understated. The extension's parity with the CLI is real but young, with a Windows-specific 403 regression still open on 2026-09-18. For anyone hitting that or needing QR codes and session names, `claude remote-control` in VS Code's integrated terminal is the fallback. Not found: an official GA date, per-plan Remote Control quotas, whether the `&` prefix still works, or which Claude Code version first made extension-hosted Remote Control work on every platform.
